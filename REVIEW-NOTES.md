fixed, because they are low or medium and fixing them has a cost or needs a
decision. High and critical findings are fixed, not listed. Newest at the top.

## Done

Recorded so a later review does not raise them again.

- Out of memory (2026-10-08, your call): the per-path guards added over several review rounds (rollback of undo steps, a canvas that said so and retried on a click, a never-throwing Rebuild, copies ordered before swaps) are gone. One handler in `Program.Failed` catches out-of-memory from any click, key or paint: each open editor saves its screenshot without asking (the edited image if there is memory to draw it, else the capture as it arrived; beside an opened file as "(edited)", never over it), a warning says where, and the editor closes on OK. Anything else gets WinForms' usual error dialog. The footprint should never get there, so one rule beats guards at every allocation. Review highs fixed: the rescue could write over the opened file (after an earlier Overwrite) and now always writes a new one; only out of memory fell back to the plain capture, now any failure does and the warning says the edits were lost; GDI+ reports a bitmap it has no memory for as `ArgumentException`, now turned into out of memory where full-size images are made (`Cut.NewBitmap`); the image was swapped before the shapes were copied, so a rescue could save mismatched annotations; anything escaping `Rescue` ended the process. Rejected: Quit on the generic dialog dropping unsaved work, which is what WinForms' own dialog did. Checked live with injected exceptions: the edited image saved as a new file beside the opened one (an earlier rescue file untouched), and with the export failing too, the capture as it arrived with the warning saying so; the editor closed on OK both times.

- Cut out mediums, second pass (2026-10-08), one commit and review each. Fixed: dropping a band clears only its own hint, so "Copied", "Saved" and errors survive; Copy catches GDI+ errors as Save does; an out-of-memory canvas says so and a click retries (not from paint, which would repaint forever), centred on the visible canvas (review high: it was centred on the image's area, off screen when zoomed); `Cut.Apply` refuses a cut outside the image or taking all of it; tests for `Across` past a crop's right edge and from above its top.

- Pen strokes across a cut (2026-10-08): samples in the band were clamped onto the seam and left stubs along it; the in-between ones are now dropped and the stroke joins straight across. Its two ends stay (clamped onto the seam if in the band), so a stroke ending in the band keeps its ink outside it: the first version dropped such a stroke whole (review high, fixed before it was used). Samples exactly on the band's edges count as in it, as for boxes. Other kinds still clamp, as boxes are squashed by their corners.

- Cut out mediums and lows (2026-10-08), one commit and one review each. Fixed: text running past the band is kept (steps go with their point: a review high, fixed); at most three full images while cutting; the band's hint goes with the band; undo/redo of a cut keeps the zoom; a refused crop's outline is erased; several cuts rebuild in one copy; each editor reads light or dark when it opens; tests for history with cuts, crop offsets, band edges, translucent pixels. Review highs fixed, over three rounds: a cut or undo that runs out of memory left shapes, crop, history and image out of step and every paint throwing; Rebuild's new cache, and then its drawing (redaction locks pixels), could throw out of a click; the shape copies made after the new image was swapped in (restoring a step, shifting for a cut) could do the same, so every copy is now made before anything changes, and the canvas is rebuilt before history is pushed; Save did not catch out of memory. Raised and rejected: "`Contains` should exclude the far edge": points sit on pixel edges, so a box drawn exactly over the band must go, not stay as a flat line (pinned by a test). "`Application.IsDarkModeEnabled` may cache": its getter reads `AppsUseLightTheme` from the registry on every call (traced through the IL of WinForms 10). "Empty cut arrays compared by reference may differ": `[]` for an array is `Array.Empty`, one instance. "No test guards `SourceCopy` in `Cut.Apply`": it draws onto a new, fully transparent bitmap, where `SourceOver` gives exactly the source, so the swap changes nothing; filling the bitmap first only to make it testable would cost every cut.
- Toolbar and Cut out review (2026-10-08). No critical or high. Raised and rejected: "`Graphics.FillRoundedRectangle` does not exist, build break": it is in System.Drawing since .NET 9, and the build and 121 tests pass. "`Cut.Apply` exact copy unverified": the pixel test covers both directions and an edge band and passes. "Icon code points unchecked": each was rendered from SegoeIcons.ttf and chosen by eye.

Images: size checked on the handle that is read, so a growing file cannot pass the limit; pipes and devices refused. Scrolling: the lost-not-end rule has a unit test. Corners: snapped is `IsWindowArranged`, not a guess from the work area.

Still areas now repeat, as in ShareX. This also closes the flat-gradient-sidebar and zebra-pane items.
